###### Overview

A layout helper that wraps a platform `Table` (or equivalent markup) placed in a placeholder. The table itself is not part of the helper: `TableWrapper` only controls scroll behaviour, sticky headers, loading, empty state, optional clickable rows, optional reorderable rows, and column width rules through CSS and JavaScript.

- The root (`.tablewrapper`) is the horizontal scroll container. When `MaxHeight` is set, it also becomes the vertical scroll container and pins the header cells (and pagination, when present) with `position: sticky`.
- `IsStickyHeader` enables a cloned header row that sticks to the top of the screen layout while the page scrolls. It is ignored when `MaxHeight` is set (internal scroll takes over).
- While `IsLoading` is `True`, the table is dimmed and a centered loading overlay is shown over the wrapper.
- When `PageCount` is `0` and the wrapper is no longer pristine, the **NoRecords** placeholder is shown. `IsPristine` keeps the empty state hidden before the first data load.
- `ColumnFixedWidths` applies fixed `table-layout` and honours `width-*` classes on cells; when off, those width classes are cleared.
- `Density` controls header and row compactness. Only `Compact` and `Default` from `SapphireDensity` are supported; other density values are not applied.
- When `HasPagination` is `True`, a pagination control is shown below the table (driven by `MaxRecords`, `StartIndex`, and `TotalCount`) and fires `PaginationNavigate` on page change. When `MaxHeight` is set, that control is pinned to the bottom of the internal scroll container.
- `data-rowid` on the `tr` is **not** sent by the server. The helper inspects every `td` in each body row; if any cell has `data-rowid`, that value is copied onto the `tr`. Click (`RowClick`) and Reorder (`Reorder`) both read the id from this `tr` attribute — not from the cells at event time. A cell may also carry `data-rowisreorderable`. When it is `false`, that row's reorder cell stays in place but does not accept a drag or edits to the position input. Any other value, or a missing attribute, leaves the row reorderable. A cell may also carry `data-roworder`. When that value is present it is copied onto the `tr` and shown in the reorder input. When it is absent, the input is the row's visual position starting at `1`. After a drag, or after a typed move is applied, inputs follow the new visual positions starting at `1`.
- When `ClickableRows` is `True`, body rows become clickable and fire `RowClick` with that row's `tr` `data-rowid`. When no cell had `data-rowid` to copy, the event receives `"missing rowid"`. Clicks on interactive cell content (`a`, `button`, `input`, `select`, `textarea`, `label`, and common ARIA / editable roles) do not fire `RowClick`. Turning `ClickableRows` off removes the handlers.
- When `ReorderableRows` is `True`, a row can be dragged from the cell in column `ReorderInputColumn` only (hover cursor is `grab`). That cell starts with a `.dots-six-vertical` grip icon, then the order control. The position input does not start a drag. A completed drag does not fire `RowClick`. Whatever was already in that cell is hidden until reorder is turned off or the column changes.
- When `ReorderImmediately` is `True` (default), a drop that changes order fires `Reorder` immediately with each row's `tr` `data-rowid` in the new visual order (JSON array string). The order cell shows only the position input (current index). The previous-order number, the arrow, and **Apply order** (`.tablewrapper-reorder-commit`) are hidden. Typing an integer in `1…N` and pressing Enter, or blurring the input, moves that row and fires `Reorder`. Out of range, empty, or non-integer values revert. `Escape`, while the input is still focused, restores the value from when it was focused and does not commit. Focusing or clicking the input does not start a drag and does not fire `RowClick`.
- When `ReorderImmediately` is `False`, reorder is staged and `Reorder` does **not** fire on drag or on typed position changes:
  - The order cell shows origin, arrow, then the intended position (`1 → 1`, `4 → 2`, …). Example: dragging the 4th row two places up yields `1 → 1`, `4 → 2`, `2 → 3`, `3 → 4`, `5 → 5`. Further drags keep those original numbers on the left and only update the intended side.
  - Typing an integer in `1…N` only updates that input (`4 → 2`). Enter and blur do **not** move the row and do **not** fire `Reorder`. Out of range, empty, or non-integer values revert. `Escape`, while the input is still focused, restores the value from when it was focused and does not move the row.
  - A bar above the table shows **Apply order**. It is disabled until the visual order differs from the session origin or a position input holds a different valid index, and while `IsLoading` is `True`. Clicking it applies those typed positions, fires `Reorder` with the current `tr` `data-rowid` list, then treats that order as the new origin (cells return to `1 → 1`, `2 → 2`, … and the button disables again).
  - While `IsLoading` is `True`, row drag is blocked and the position inputs are disabled.

###### Input parameters

| Name                | Type              | Description                                                                                                                                                                                                                                                                               |
| ------------------- | ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ClickableRows`     | `Boolean`         | When `True`, makes body rows clickable and fires `RowClick` with the `tr`'s `data-rowid` (copied from a `td[data-rowid]`). Interactive cell content does not trigger `RowClick`. When `False`, click handlers are removed.                                                                |
| `ColumnFixedWidths` | `Boolean`         | When `True`, uses fixed table layout and applies `width-*` size classes to columns. When `False`, those width classes are unset.                                                                                                                                                          |
| `Density`           | `SapphireDensity` | Visual density of header and body cells. Supported values: `Compact` (tighter padding, unsets the default 48px header/row height) and `Default` (standard size). Other `SapphireDensity` entries (`Dense`, `Comfortable`) are not used by this helper.                                    |
| `HasPagination`     | `Boolean`         | When `True`, shows the pagination control below the table (driven by `MaxRecords`, `StartIndex`, and `TotalCount`) and fires `PaginationNavigate` on page change. When `MaxHeight` is set, pagination is pinned to the bottom of the internal scroll. When `False`, pagination is hidden. |
| `Height`            | `Integer`         | Fixed height of the wrapper in pixels. When `0` / unset, height is not forced.                                                                                                                                                                                                            |
| `IsLoading`         | `Boolean`         | Shows a centered loading overlay and dims the table. Clearing loading also exits the pristine state.                                                                                                                                                                                      |
| `IsPristine`        | `Boolean`         | Marks the initial / untouched state. While pristine, an empty `PageCount` does not show the no-records UI.                                                                                                                                                                                |
| `IsStickyHeader`    | `Boolean`         | Pins a cloned header to the top of the screen layout on vertical page scroll. Disabled automatically when `MaxHeight` is set.                                                                                                                                                             |
| `MaxHeight`         | `Integer`         | Maximum height of the wrapper in pixels. When greater than `0`, enables internal vertical scroll with a sticky header (and sticky pagination). When `0`, no max-height.                                                                                                                   |
| `MaxRecords`        | `Integer`         | For pagination: Number of records per page                                                                                                                                                                                                                                                |
| `PageCount`         | `Integer`         | Record length for the current page. When 0 it displays the NoRecords placeholder. Otherwise, its always hidden                                                                                                                                                                            |
| `ReorderableRows`    | `Boolean`         | When `True`, the `ReorderInputColumn` cell is the drag handle for its row and shows a `.dots-six-vertical` grip plus a position input. Hover on that cell shows a grab cursor. The position input does not start a drag. See `ReorderImmediately` for when `Reorder` fires. |
| `ReorderInputColumn` | `Integer`         | 1-based body column that hosts the drag grip and reorder position input when `ReorderableRows` is `True`. Default `1` (first cell). Only this cell starts a row drag. Values below `1` are treated as `1`. A column past the row's cell count is ignored for that row. Changing it restores the previous column and moves the control. |
| `ReorderImmediately` | `Boolean`         | When `True` (default), a drop that changes order fires `Reorder` immediately, and the order cell is only the position input. Enter or blur moves the row within `1…N` and fires `Reorder` (invalid reverts; `Escape` restores the focused value and does not commit). **Apply order** is not shown. When `False`, drag rearranges the DOM only. Typing a position updates the input and does not move the row on Enter or blur. The cell shows original → intended (`origin →` editable index). **Apply order** is the only commit: it applies typed positions, then fires `Reorder`. It is disabled until the order actually changed or a typed position differs from the current index. |
| `StartIndex`        | `Integer`         | For pagination: Set the initial index to start pagination                                                                                                                                                                                                                                 |
| `TotalCount`        | `Long Integer`    | For pagination: Total records of list                                                                                                                                                                                                                                                     |

<hr>

###### Placeholders

| Name        | Description                                                                                                         |
| ----------- | ------------------------------------------------------------------------------------------------------------------- |
| `Table`     | The platform table to enhance. Not owned by the helper; styled and observed at runtime.                             |
| `NoRecords` | Empty-state content shown when there are no records after the first load (`PageCount` is `0` and not `IsPristine`). |

###### Events

| Name                 | Description                                                                                                                                                                                                  | Arguments                   |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------- |
| `PaginationNavigate` | Event triggered on navigate. New start index value returned.                                                                                                                                                 | `NewStartIndex` (`Integer`) |
| `Reorder`            | Fired after a drop, or an Enter or blur on the position input, that changes order when `ReorderImmediately` is `True`, or when **Apply order** is clicked when `ReorderImmediately` is `False`. Not fired by staged drags, or by typing, Enter, or blur on the position input in staged mode. Each id is the `tr`'s `data-rowid` (copied from a `td[data-rowid]` when present). JSON array string, e.g. `["id-1","id-2"]`. | `RowIds` (`Text List`)      |
| `RowClick`           | Fired when a clickable row is activated (not when the click target is interactive cell content). `RowId` is the `tr`'s `data-rowid`, copied from a `td[data-rowid]` in the row; otherwise `"missing rowid"`. | `RowId` (`Text`)            |
