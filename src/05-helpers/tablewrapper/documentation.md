###### Overview

A layout helper that wraps a platform `Table` (or equivalent markup) placed in a placeholder. The table itself is not part of the helper: `TableWrapper` only controls scroll behaviour, sticky headers, loading, empty state, optional clickable rows, optional reorderable rows, and column width rules through CSS and JavaScript.

- The root (`.tablewrapper`) is the horizontal scroll container. When `MaxHeight` is set, it also becomes the vertical scroll container and pins the header cells (and pagination, when present) with `position: sticky`.
- `IsStickyHeader` enables a cloned header row that stays pinned while the table is on screen. It sits below a sticky FilterBar when that bar is also pinned. It is ignored when `MaxHeight` is set (internal scroll takes over). The clone is rebuilt when the table is refreshed.
- While `IsLoading` is `True`, the table is dimmed and a centered loading overlay is shown over the wrapper.
- When `PageCount` is `0` and the wrapper is no longer pristine, the **NoRecords** placeholder is shown. `IsPristine` keeps the empty state hidden before the first data load.
- `ColumnFixedWidths` applies fixed `table-layout` and honours `width-*` classes on cells; when off, those width classes are cleared. The header sets the rule: every body cell gets the `width-*`, `min-width-*` and `max-width-*` classes of the header cell in its column, and any different width class of its own is removed. When there is no header, or the header cell has no width class, each cell keeps its own. Turning the option off, or removing the class from the header, gives cells back their own classes.
- A column is hidden, header included, when its header cell and all its body cells are empty. A column with a title stays visible even when it has no data. A cell is empty when it has no visible text and no image, icon (`data-iconname`), SVG, media or form element; empty platform wrappers and `&nbsp;` do not count as content. With no body rows nothing is hidden.
- A column whose body cells each hold only a checkbox, or nothing, is capped at `CheckboxColumnMaxWidth` (default `100` px). At least one body cell must have a checkbox, and a cell with any text or other content keeps the column uncapped. The header cell of that column gets the same cap, whatever it holds. With no body rows nothing is capped.
- When `ReorderableRows` is `True`, every cell in the `ReorderColumn` column, and the header cell above it, is capped at `ReorderColumnMaxWidth` (default `120` px).
- Both caps also set the cell's `width`, because a table cell ignores `max-width` on its own. They apply with `ColumnFixedWidths` on or off and override any `width-*` class on those cells. Capped cells, headers included, are centered. A value of `0` or less uses the default.
- `Density` controls header and row compactness. Only `Compact` and `Default` from `SapphireDensity` are supported; other density values are not applied.
- When `HasPagination` is `True`, a pagination control is shown below the table (driven by `MaxRecords`, `StartIndex`, and `TotalCount`) and fires `PaginationNavigate` on page change. When `MaxHeight` is set, that control is pinned to the bottom of the internal scroll container.
- `data-rowid` on the `tr` is **not** sent by the server. The helper inspects every `td` in each body row; if any cell has `data-rowid`, that value is copied onto the `tr`. Click (`RowClick`) and Reorder (`Reorder`) both read the id from this `tr` attribute — not from the cells at event time. A cell may also carry `data-rowisreorderable`. When it is `false`, that row's reorder cell stays in place but does not accept a drag or edits to the position input. Any other value, or a missing attribute, leaves the row reorderable. A cell may also carry `data-roworder`. When that value is present it is copied onto the `tr`. When `ReorderInputs` is `True` and the value is present, it is shown in the reorder input; when it is absent, the input is the row's visual position starting at `1`. After a drag, or after a typed move is applied, inputs follow the new visual positions starting at `1`. When `ReorderInputs` is `False`, `data-roworder` is still copied onto the `tr` and a drag still updates it to the visual position, but it is not shown.
- When `ClickableRows` is `True`, body rows become clickable and fire `RowClick` with that row's `tr` `data-rowid`. When no cell had `data-rowid` to copy, the event receives `"missing rowid"`. Clicks on interactive cell content (`a`, `button`, `input`, `select`, `textarea`, `label`, and common ARIA / editable roles) do not fire `RowClick`. Turning `ClickableRows` off removes the handlers.
- When `ReorderableRows` is `True`, a row can be dragged from the cell in column `ReorderColumn` only (hover cursor is `grab`). That cell starts with a `.dots-six-vertical` grip icon. When `ReorderInputs` is `True`, the order control follows the grip. The position input does not start a drag. A completed drag does not fire `RowClick`. Whatever was already in that cell is hidden until reorder is turned off or the column changes.
- When `ReorderInputs` is `True` (default), the reorder cell includes a text input for typing a new order. When `ReorderInputs` is `False`, that input, the previous-order number, and the arrow are hidden. Reorder is drag-only: a drop still follows `ReorderImmediately`, and `ReorderInput` does not fire.
- When `ReorderImmediately` is `True` (default), a drop that changes order fires `Reorder` immediately with each row's `tr` `data-rowid` in the new visual order (JSON array string). When `ReorderInputs` is `True`, the order cell shows only the position input (current index). The previous-order number, the arrow, and **Apply order** (`.tablewrapper-reorder-commit`) are hidden. Typing a positive integer and pressing Enter, or blurring the input, fires `ReorderInput` (not `Reorder`) with a one-item JSON array for that row's `data-rowid` and a one-item JSON array for the typed order. A value within the current page also moves that row. A value past the last row on this page is not moved locally and still fires `ReorderInput`. Empty, zero, or non-integer values revert. `Escape`, while the input is still focused, restores the value from when it was focused and does not commit. Focusing or clicking the input does not start a drag and does not fire `RowClick`.
- When `ReorderImmediately` is `False`, reorder is staged and `Reorder` does **not** fire on drag or on typed position changes. When `ReorderInputs` is `False`, the cell is the grip only and **Apply order** commits the drag. When `ReorderInputs` is `True`:
  - The order cell shows origin, arrow, then the intended position (`1 → 1`, `4 → 2`, …). Example: dragging the 4th row two places up yields `1 → 1`, `4 → 2`, `2 → 3`, `3 → 4`, `5 → 5`. Further drags keep those original numbers on the left and only update the intended side.
  - Typing a positive integer only updates that input (`4 → 2`, or `4 → 40` when that order is outside this page). Enter and blur do **not** move the row and do **not** fire `Reorder`. Empty, zero, or non-integer values revert. `Escape`, while the input is still focused, restores the value from when it was focused and does not move the row.
  - A bar above the table shows **Apply order**. It is disabled until the visual order differs from the session origin or a position input holds a different valid index, and while `IsLoading` is `True`. Clicking it applies those typed positions. If any position input was committed, it fires `ReorderInput` (not `Reorder`) with the committed rows' `data-rowid` values and the orders that were typed, each as a JSON array string in the same sequence. If the click only commits a drag, it fires `Reorder` with the current `tr` `data-rowid` list. It then treats that order as the new origin (cells return to `1 → 1`, `2 → 2`, … and the button disables again).
  - While `IsLoading` is `True`, row drag is blocked and the position inputs are disabled.

###### Input parameters

| Name                | Type              | Description                                                                                                                                                                                                                                                                               |
| ------------------- | ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CheckboxColumnMaxWidth` | `Integer`   | Width cap, in pixels, for a column whose body cells hold only a checkbox (or nothing). Also applies to that column's header cell. Default `100`. `0` or less uses the default. |
| `ClickableRows`     | `Boolean`         | When `True`, makes body rows clickable and fires `RowClick` with the `tr`'s `data-rowid` (copied from a `td[data-rowid]`). Interactive cell content does not trigger `RowClick`. When `False`, click handlers are removed.                                                                |
| `ColumnFixedWidths` | `Boolean`         | When `True`, uses fixed table layout and applies `width-*` size classes to columns. Header width classes are copied to every body cell in that column and replace the cell's own. When `False`, those width classes are unset.                                                         |
| `Density`           | `SapphireDensity` | Visual density of header and body cells. Supported values: `Compact` (tighter padding, unsets the default 48px header/row height) and `Default` (standard size). Other `SapphireDensity` entries (`Dense`, `Comfortable`) are not used by this helper.                                    |
| `HasPagination`     | `Boolean`         | When `True`, shows the pagination control below the table (driven by `MaxRecords`, `StartIndex`, and `TotalCount`) and fires `PaginationNavigate` on page change. When `MaxHeight` is set, pagination is pinned to the bottom of the internal scroll. When `False`, pagination is hidden. |
| `Height`            | `Integer`         | Fixed height of the wrapper in pixels. When `0` / unset, height is not forced.                                                                                                                                                                                                            |
| `IsLoading`         | `Boolean`         | Shows a centered loading overlay and dims the table. Clearing loading also exits the pristine state.                                                                                                                                                                                      |
| `IsPristine`        | `Boolean`         | Marks the initial / untouched state. While pristine, an empty `PageCount` does not show the no-records UI.                                                                                                                                                                                |
| `IsStickyHeader`    | `Boolean`         | Pins a cloned header while this table is on screen. Stacks under a sticky FilterBar. Disabled automatically when `MaxHeight` is set. Released once the table has scrolled past.                                                                                                            |
| `MaxHeight`         | `Integer`         | Maximum height of the wrapper in pixels. When greater than `0`, enables internal vertical scroll with a sticky header (and sticky pagination). When `0`, no max-height.                                                                                                                   |
| `MaxRecords`        | `Integer`         | For pagination: Number of records per page                                                                                                                                                                                                                                                |
| `PageCount`         | `Integer`         | Record length for the current page. When 0 it displays the NoRecords placeholder. Otherwise, its always hidden                                                                                                                                                                            |
| `ReorderableRows`    | `Boolean`         | When `True`, the `ReorderColumn` cell is the drag handle for its row and shows a `.dots-six-vertical` grip. When `ReorderInputs` is `True`, that cell also shows a position input, which does not start a drag. Hover on the cell shows a grab cursor. See `ReorderImmediately` for when `Reorder` fires. |
| `ReorderColumn`      | `Integer`         | 1-based body column that hosts the drag grip when `ReorderableRows` is `True`, and the position input when `ReorderInputs` is also `True`. Default `1` (first cell). Only this cell starts a row drag. Values below `1` are treated as `1`. A column past the row's cell count is ignored for that row. Changing it restores the previous column and moves the control. |
| `ReorderColumnMaxWidth` | `Integer`  | Width cap, in pixels, for every cell in the `ReorderColumn` column and the header cell above it, when `ReorderableRows` is `True`. Default `120`. `0` or less uses the default. |
| `ReorderImmediately` | `Boolean`         | When `True` (default), a drop that changes order fires `Reorder` immediately, and the order cell is only the position input (when `ReorderInputs` is `True`). Enter or blur fires `ReorderInput` with one-item lists for any positive integer, including an order past this page (empty, zero, or non-integer reverts; `Escape` restores the focused value and does not commit). A value within the current page also moves that row. **Apply order** is not shown. When `False`, drag rearranges the DOM only. Typing a position updates the input and does not move the row on Enter or blur. The cell shows original → intended (`origin →` editable index). **Apply order** is the only commit: it applies typed positions, then fires `ReorderInput` for those typed rows, or `Reorder` when the commit is drag-only. It is disabled until the order actually changed or a typed position differs from the current index. When `ReorderInputs` is `False`, only this drag path applies. |
| `ReorderInputs`      | `Boolean`         | When `True` (default), the reorder cell shows a text input so the user can type a new order. When `False`, the position input, the previous-order number, and the arrow are hidden. Order changes come from dragging the grip, and `ReorderInput` does not fire. |
| `StartIndex`        | `Integer`         | For pagination: Set the initial index to start pagination                                                                                                                                                                                                                                 |
| `TotalCount`        | `Long Integer`    | For pagination: Total records of list                                                                                                                                                                                                                                                     |

###### Placeholders

| Name        | Description                                                                                                         |
| ----------- | ------------------------------------------------------------------------------------------------------------------- |
| `Table`     | The platform table to enhance. Not owned by the helper; styled and observed at runtime.                             |
| `NoRecords` | Empty-state content shown when there are no records after the first load (`PageCount` is `0` and not `IsPristine`). |

###### Events

| Name                 | Description                                                                                                                                                                                                  | Arguments                   |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------- |
| `PaginationNavigate` | Event triggered on navigate. New start index value returned.                                                                                                                                                 | `NewStartIndex` (`Integer`) |
| `Reorder`            | Fired after a drop that changes order when `ReorderImmediately` is `True`, or when **Apply order** commits a drag-only change when `ReorderImmediately` is `False`. Not fired by typed position commits (`ReorderInput` fires instead), staged drags, or by typing, Enter, or blur on the position input in staged mode. Each id is the `tr`'s `data-rowid` (copied from a `td[data-rowid]` when present). JSON array string, e.g. `["id-1","id-2"]`. | `RowIds` (`Text List`)      |
| `ReorderInput`       | Fired when a position input is committed. Not fired when `ReorderInputs` is `False`. When `ReorderImmediately` is `True`, Enter or blur on one input sends one-item lists. When `ReorderImmediately` is `False`, **Apply order** sends every committed input, in edit order. `RowIds` and `NewOrders` are JSON array strings of equal length, e.g. `["id-4"]` and `[2]`. | `RowIds` (`Text`), `NewOrders` (`Text`) |
| `RowClick`           | Fired when a clickable row is activated (not when the click target is interactive cell content). `RowId` is the `tr`'s `data-rowid`, copied from a `td[data-rowid]` in the row; otherwise `"missing rowid"`. | `RowId` (`Text`)            |
